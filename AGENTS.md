# AGENTS.md

This repo is a **Helm chart** (`neowiki/`) that deploys the NeoWiki stack (MediaWiki +
Neo4j + a SPARQL backend) to Kubernetes. It is not the NeoWiki application itself.

## Layout

- `neowiki/` — the chart. This is what gets packaged/released.
- `src/NeoWiki/` — a separate checkout of the upstream
  [ProfessionalWiki/NeoWiki](https://github.com/ProfessionalWiki/NeoWiki) app repo, kept only
  as a **reference** for how the demo (`make demo` / `Docker/docker-compose.yml` /
  `Docker/SettingsTemplate.php`) actually wires env vars and runs install/seed steps. It has its
  own git remote and is gitignored (`.gitignore` = `src`) — never edit or commit anything under it.
  If it doesn't exist, suggest cloning it into `src/NeoWiki`.
- `neowiki/files/LocalSettings.php` is a **k8s-adapted copy** of
  `src/NeoWiki/Docker/SettingsTemplate.php`. If you change env-driven config in one, check
  whether the other needs the same fix — they have drifted before.
- `old-plans/` — personal archive for implementation plans. Ignore it unless doing historical research.
  Gitignored (`.gitignore` = `old-plans`) — never edit or commit anything under it.
- `README.md` (repo root) — short pointer doc, not packaged. Keep it to a one/two-line summary
  plus a link to `neowiki/README.md`; don't duplicate chart docs into it.
- `neowiki/README.md` — the human-facing chart docs, packaged/released with the chart (standard
  Helm chart README: prerequisites, install/uninstall, full values reference, caveats). See
  "Maintaining the READMEs" below.

## Commands

```
helm dependency update neowiki   # required before lint/template/install: neo4j subchart isn't vendored in git
helm lint neowiki --set mediawiki.adminPassword=<10+ chars> --set mediawiki.secretToken=<64+ chars>
helm template neowiki ./neowiki --set mediawiki.adminPassword=<10+ chars> --set mediawiki.secretToken=<64+ chars>
```

- `mediawiki.adminPassword` (>=10 chars) and `mediawiki.secretToken` (>=64 chars) are
  `required(...)` in templates with **no defaults in values.yaml, by design** — `helm lint`,
  `helm template`, and `helm install` all require `--set` for both (bare runs fail/warn on purpose).
  Don't "fix" this by adding defaults.
- `neowiki/Chart.lock` and `neowiki/charts/*.tgz` are generated by `helm dependency update` and
  currently untracked; the chart won't lint/template without them present.
- No app-level test suite in this repo. Verification is `helm lint` + `helm template` (and,
  when available, `helm install` against a real/kind cluster).

## Chart-specific gotchas

- The neo4j dependency is the **pinned upstream chart** (`helm.neo4j.com/neo4j`
  `2026.7.1`, `Chart.yaml`). Its values live under `neo4j.*` in `values.yaml` and follow that
  subchart's schema, not this chart's conventions — e.g. `neo4j.neo4j.name` is **required** by
  the subchart, and storage is `neo4j.volumes.data.mode` /
  `defaultStorageClass.requests.storage` (there is no `size` key). Check the actual subchart in
  `neowiki/charts/neo4j-*.tgz` before assuming a values key exists.
- Neo4j LB service name is derived as `<neo4j.neo4j.name>-lb-neo4j`, and its auth secret as
  `<neo4j.neo4j.name>-auth` (key `NEO4J_AUTH`, value `neo4j/<password>`). This chart must never
  create a Secret with that same name (would shadow the subchart's).
- MariaDB is provisioned via the **MariaDB Kubernetes operator** CRDs
  (`k8s.mariadb.com/v1alpha1`: `MariaDB`, `Database`, `User`, `Grant` in
  `templates/mariadb*.yaml`), not a MariaDB Helm subchart. A cluster without that operator's
  CRDs installed cannot actually run this chart, even though `helm template` will still render.
- Assumes a default StorageClass exists (PVCs for mediawiki images, qlever/oxigraph, neo4j,
  mariadb).
- Naming helpers live in `templates/_helpers.tpl` (`neowiki.fullname`, `neowiki.mariadb.*`,
  `neowiki.neo4j.*`, `neowiki.qlever.*`, `neowiki.oxigraph.*`) — use these instead of
  re-deriving resource/service names inline in new templates.
- `.github/workflows/chart-release.yaml` runs `helm/chart-releaser-action` on push to `main`
  with `charts_dir: .` (repo root, not `neowiki/`) — chart-releaser auto-discovers chart
  directories from there.

## Maintaining the READMEs

- `neowiki/README.md` is the source of truth for human-facing docs and ships inside the packaged
  chart (ends up on the chart's index/ArtifactHub page). Update it whenever a change would be
  visible to someone installing the chart:
  - Adding, renaming, removing, or changing the default of a `values.yaml` key — update the
    matching table/row in the "Configuration" section.
  - Adding a new required value (like `mediawiki.adminPassword` / `mediawiki.secretToken`) —
    document it as required, with no default, and show it in the install example.
  - Changing prerequisites (e.g. dropping/adding the MariaDB operator dependency, minimum
    Kubernetes/Helm version, StorageClass assumptions).
  - Adding/removing a chart dependency (`Chart.yaml` `dependencies:`) — update "Prerequisites"
    and "Source Code".
  - Changing install/uninstall behavior (new hooks, new PVCs that survive uninstall, etc.).
  - Adding a new gotcha/caveat that also belongs in this file's "Chart-specific gotchas" —
    add it to both; keep the AGENTS.md version terse/agent-facing and the README version
    explanatory/user-facing.
- Root `README.md` should stay a short pointer (summary + link to `neowiki/README.md`). Don't let
  it accumulate chart details — if you're tempted to add a paragraph there, it almost certainly
  belongs in `neowiki/README.md` instead.
- There's no automated check that the README matches `values.yaml` — when reviewing/making a
  values change, manually diff it against the "Configuration" tables in `neowiki/README.md`.
